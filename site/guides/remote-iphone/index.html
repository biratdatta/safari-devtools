Remote mode: debug an iPhone from your computer over Wi-Fi

Updated 2026-10-20 · 2 min read

Remote mode connects a page on your phone to a viewer on your computer. You see the phone's console and network live, and anything you type runs on the phone.

1. Start the relay

You need Node 18 or later on the computer. There's nothing else to install.

git clone https://github.com/biratdatta/safari-devtools
cd safari-devtools
node standalone/remote/relay.js

It prints your computer's address on the network, for example http://192.168.1.20:9230.

2. Connect the phone

The phone must be on the same Wi-Fi. To try it, open http://<computer-ip>:9230/demo on the phone. For your own page, either load the tool from the relay:

<script src="http://<computer-ip>:9230/safari-devtools.js" data-remote="http://<computer-ip>:9230"></script>

or, if the page already loads Safari DevTools, add ?sdt-remote=http://<computer-ip>:9230 to its address.

3. Watch on the computer

Open http://localhost:9230. Pick the device, then read logs and requests as they happen and type JavaScript to run on the phone.

Security

  • The viewer and the control API only answer requests from the computer itself, unless you start the relay with a token: SDT_TOKEN=some-secret node standalone/remote/relay.js.
  • Only run the relay on networks you trust.

HTTPS pages

Safari blocks an https:// page from talking to an http:// relay (mixed content). Use remote mode with your local http:// development server, or put the relay behind HTTPS.

For automation and AI agents

The relay also exposes an HTTP API (/api/devices, /api/logs, /api/network, /api/eval, /api/call) and an MCP server, so tests and agents like Claude or Cursor can read and drive the page on the phone.
