How to debug WKWebView and in-app browsers on iOS

Updated 2026-10-20 · 2 min read

Pages inside apps (WKWebView, in-app browsers, hybrid apps) are hard to debug: Safari's Web Inspector only sees them if the app allows it. Here are your options.

If you build the app: make it inspectable

Since iOS 16.4, a WKWebView only appears in Safari's Develop menu when the app opts in:

if #available(iOS 16.4, *) {
    webView.isInspectable = true   // debug builds only
}

Inject Safari DevTools into the WebView

This works without a Mac and in builds where inspection is off. Bundle safari-devtools.js and add it as a user script that runs before the page's own code:

let url = Bundle.main.url(forResource: "safari-devtools", withExtension: "js")!
let source = try String(contentsOf: url, encoding: .utf8)
let script = WKUserScript(source: source, injectionTime: .atDocumentStart, forMainFrameOnly: true)
configuration.userContentController.addUserScript(script)

A round button appears in the page; tap it to open the panel. Include it only in debug or internal builds.

React Native, Capacitor and Cordova

  • react-native-webview: pass the file's contents to the injectedJavaScriptBeforeContentLoaded prop.
  • Capacitor and Cordova: add the script tag first in your app's index.html for development builds.

Pages you don't control

If the page is someone else's (for example, a link opened in an in-app browser), you usually can't inject anything. Open the same URL in Safari and use the bookmarklet instead.

Android WebViews

Call WebView.setWebContentsDebuggingEnabled(true) in debug builds, then open chrome://inspect on your computer with the phone connected by USB. Or inject Safari DevTools the same way as on iOS.
