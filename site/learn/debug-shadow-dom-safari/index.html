Debugging web components and shadow DOM in Safari

Updated 2026-10-20 · 2 min read

Web components hide their insides in shadow DOM, which makes them harder to debug. Safari DevTools is built with them in mind.

See inside shadow roots

The Elements tree shows #shadow-root (open) under each component and what each <slot> renders. The picker selects elements inside shadow DOM directly, and the Styles pane shows :host rules alongside the element's own.

The Component pane

Select a custom element and open Component to see:

  • its properties, which you can edit live, and observed attributes;
  • its slots and what's assigned to each;
  • the ::part() hooks it exposes for styling;
  • the CSS custom properties it reads, with their current values;
  • extra details for Lit and Angular components.

Find elements across shadow boundaries

Search the Elements tree with normal CSS selectors; the search goes into open shadow roots. In the automation API and Playwright fixture, use >>> to pierce shadow roots:

SafariDevTools.automation.element('user-card >>> .label');

Accessibility inside components

The Accessibility tab's tree and the Audit tab both go through shadow DOM, so you can check names and roles of controls inside your components.

Closed shadow roots (mode: 'closed') are hidden from page scripts by design, so no in-page tool can see inside them.
