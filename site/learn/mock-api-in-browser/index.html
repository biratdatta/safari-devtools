How to mock, block and slow down API calls in the browser

Updated 2026-10-20 · 2 min read

Most bugs hide in the paths you rarely see: the API returns a 500, the response is empty, or the network is slow. Safari DevTools lets you force those cases right in the page, in Safari, Chrome or on iPhone.

Mock a response in two clicks

  1. Open the Network tab and find the request.
  2. Right-click it and choose Mock. Edit the status, headers and body, then reload or repeat the action.

Mocked requests are tagged mock in the list, so you always know what's real.

Rules: mock, block or delay by URL

Under Rules, match requests by text, a * wildcard or a /regex/, optionally by method, and choose an action:

  • Mock: return your own status, headers and body.
  • Block: make the request fail, to test error handling.
  • Delay: add latency to one endpoint, to test spinners and race conditions.

Rules are saved per site, so they survive reloads.

Throttle the whole page

Pick Fast 4G, Fast 3G, Slow 3G or Offline from the throttling menu to see how the page behaves on a poor connection.

From the console or your tests

// in the console, or from any script
SafariDevTools.automation.mock('/api/cart', { status: 500, body: { error: 'down' } });
SafariDevTools.automation.throttle('slow3g');

// in Playwright, before the page loads
await devtools.mockBeforeLoad('/api/coupon', { status: 410, body: { error: 'Coupon expired' } });

Mocking covers fetch and XMLHttpRequest. It runs in the page, so it can't change requests made by the browser itself, such as images or form posts that navigate away.
