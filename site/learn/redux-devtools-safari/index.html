Redux DevTools in Safari (and NgRx, Zustand)

Updated 2026-10-20 · 2 min read

The Redux DevTools extension exists for Chrome and Firefox, but not for Safari or iPhone. Safari DevTools fills that gap.

How it works

Safari DevTools provides window.__REDUX_DEVTOOLS_EXTENSION__ and window.__REDUX_DEVTOOLS_EXTENSION_COMPOSE__, the same hooks the official extension uses. Libraries that look for the extension connect to Safari DevTools instead, with no code changes.

LibraryWhat to do
Redux ToolkitNothing. configureStore enables DevTools by default in development.
Plain ReduxUse window.__REDUX_DEVTOOLS_EXTENSION_COMPOSE__ to compose your enhancers, as the Redux docs describe.
NgRxAdd provideStoreDevtools() (or StoreDevtoolsModule.instrument()).
ZustandWrap your store with the devtools middleware.

What you get

Open Components → Store to see every action with its payload, which keys changed, and the full state after it. Jump to any earlier action to time-travel the UI, or Dispatch a new action by hand.

One requirement: load it first

Stores look for the extension when they're created, so Safari DevTools must load before your app. The browser extensions do this automatically. With a script tag, put it first in <head>. The bookmarklet loads too late for store connection; use it for everything else.
