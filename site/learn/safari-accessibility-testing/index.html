Accessibility testing in Safari: tree, tab order and contrast

Updated 2026-10-20 · 2 min read

The Accessibility tab in Safari DevTools gives you four quick checks that catch most problems before a full screen-reader pass.

1. The accessibility tree

See each element's role, accessible name (and where the name comes from) and states such as expanded, pressed or disabled, the way VoiceOver receives them. It goes through shadow DOM and slots, so web components are covered. Buttons, links and images with no name are flagged.

2. Tab order

Turn on the overlay and every focusable element gets a numbered badge on the page, joined by a dashed path, in the order the keyboard visits them. Positive tabindex values, a common cause of confusing order, are flagged.

3. Focus tracker

Start tracking, then use the page with the keyboard. Every focus change is logged, and two common bugs are flagged automatically: focus escaping an open dialog, and focus getting lost to the page body.

4. Contrast fixer

Pick any text on the page to see its contrast ratio against the real background, with the AA and AAA thresholds (4.5:1 for normal text, 3:1 for large text at AA). If it fails, you get:

  • the closest passing colours from your own design tokens, and
  • the nearest passing shade of the same colour.

Click Apply to try it on the page; the change shows up in the Changes tab, ready to copy as CSS.

Also useful

  • The Audit tab lists missing alt text, labels, duplicate ids, heading order and more, including inside shadow DOM.
  • The Device tab can emulate reduced motion and larger text.

These checks catch the common, mechanical problems. Still test with VoiceOver on a real device before shipping.
