Safari-only CSS bugs on iPhone, and how to fix them

Updated 2026-10-20 · 2 min read

A handful of issues cause most "only broken on iPhone" reports. The Safari DevTools Audit tab checks for all of these, and the Device tab shows the real viewport numbers.

Inputs zoom the page when tapped

iOS Safari zooms in when you focus a field whose font size is under 16px. Fix: give inputs, selects and textareas font-size: 16px or more.

100vh is taller than the screen

On iPhone, 100vh is the height with the toolbars hidden, so content sits behind them. Use the newer units: 100svh (small viewport), 100lvh (large) or 100dvh (changes as the toolbar moves). The Device tab shows the measured value of each.

Content under the notch or home indicator

To use the full screen, add viewport-fit=cover to the viewport meta tag, then pad edges with env(safe-area-inset-top), -bottom, -left and -right. The Device tab's safe-area overlay shows where those insets fall.

<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">
.toolbar { padding-bottom: env(safe-area-inset-bottom); }

Sticky headers that don't stick

position: sticky stops working when an ancestor has overflow: hidden, auto or scroll. Move the overflow to a different element, or use overflow: clip.

Fixed elements that scroll away

A position: fixed element inside an ancestor with a transform, filter or will-change: transform becomes fixed to that ancestor instead of the screen. Move it outside the transformed element.

Videos that won't autoplay

iOS only autoplays inline video that is muted and has playsinline.

Sideways scrolling

One element wider than the screen makes the whole page scroll sideways. The Audit tab lists the culprits; Outline all elements in the Device tab makes them easy to spot.

Tap targets too small

Aim for at least 44 × 44 points for anything tappable, as Apple's guidelines suggest. The Audit tab flags smaller ones.
